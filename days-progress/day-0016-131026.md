## Разобрался

- **Галлюцинации** — не баг конкретного запроса, а архитектурное свойство LLM: модель не "проверяет факт", а генерирует наиболее вероятное продолжение текста (next-token prediction). У неё нет отдельного модуля "база истинных фактов" для сверки сгенерированного ответа.
  - Причина 1 (архитектурная): нет встроенного фактчек-механизма, один проход генерации без второго шага "а правда ли это".
  - Причина 2 (RLHF-тренировка): разметчики систематически занижали оценку ответам "не знаю" и завышали уверенным, но неточным ответам → модель статистически выучила, что уверенный тон получает более высокий reward.
  - Триггеры, усиливающие галлюцинации: редкий/отсутствующий в данных факт, переполненный контекст, неудачная саммаризация (важный факт "вытолкнут" или размыт — модель реконструирует по шаблону, а не по факту).
- **Next-token prediction**: модель не "знает" ответ целиком заранее, а строит его последовательно — на каждом шаге считает вероятности для следующего токена с учётом всего, что уже сгенерировано, и выбирает наиболее вероятный. "Правильный" токен при тренировке = то, что реально стояло в тексте, а не истина.
- **RLHF (Reinforcement Learning from Human Feedback)**: модель генерирует несколько ответов → человек ранжирует → на ранжированиях тренируют отдельную reward model (предсказывает "понравился бы ответ человеку") → основную модель дообучают через RL, повышая вероятность паттернов с высоким reward. Та же механика, что dog training (награда → выше вероятность повторить поведение), просто "награда" — градиентный шаг, а не печенька.
- **Tool calling**: модель не делает keyword-matching по промпту — она через тот же next-token prediction, но дообученный на примерах tool-use, по смыслу всего запроса решает, что генерация structured tool-call (JSON с именем функции и аргументами) сейчас вероятнее, чем обычный текст. Вызов реально выполняет backend-код, результат возвращается модели как часть контекста, дальше модель формулирует финальный ответ. Это прямой механизм grounding — замена вероятностной догадки на реальные данные.
  - Failure modes: модель может сгенерировать неверные аргументы или вызвать не тот tool (hallucinated call) → нужна валидация на backend; критичные операции (перевод денег) нельзя давать модели вызывать напрямую без human-in-the-loop.
- **ИИ и открытия**: LLM в чистом виде (текст → текст) способен на интерполяцию (комбинирование уже известного), но не на экстраполяцию за пределы тренировочных данных — нет внешнего валидатора, отсекающего галлюцинации. Контрпример — AlphaFold и материаловедческие модели: они дают реальные открытия, но не через чистый текстовый LLM, а через модели, завязанные на объективный внешний валидатор (физический эксперимент/симуляция). ИИ — ускоритель исследования (генерация гипотез, поиск паттернов), а не источник истины.
- **Модель vs LLM**: LLM — подмножество моделей (transformer, обучен на предсказание следующего токена на тексте). Любая ML-система (линейная регрессия, классификатор спама) — тоже "модель", но не LLM.
- **Чем отличаются Claude / Codex / Antigravity / DeepSeek**: это смесь разных уровней абстракции, не все сравнимо напрямую.
  - Claude, DeepSeek — сами LLM (разных компаний).
  - Codex, Antigravity — agentic-продукты (обвязка: tool calling цикл, работа с файлами, планирование) поверх LLM других компаний (GPT и Gemini соответственно).
  - Различия между самими LLM — не в архитектуре (transformer у всех), а в data curation + RLHF-приоритетах: какой "типичный пользователь" был в голове у команды разметки (разработчик vs обычный человек vs энтерпрайз).
- **Тренировочные данные не продаются между компаниями одинаково**: пересекается только публичный скрейпинг интернета (Common Crawl и т.п.). Проприетарные/лицензированные данные и RLHF-разметка — эксклюзивны для каждой компании (свои вендоры разметки, свои гайдлайны "что считать хорошим ответом"). Это основной источник конкурентного преимущества и объяснение разного "характера" моделей.
- **MoE (Mixture of Experts)**: вместо того чтобы на каждый токен считали все параметры модели (dense), router (отдельная обучаемая сеть) выбирает небольшое подмножество "экспертов" (блоков feed-forward слоя) для каждого конкретного токена. Общее число параметров огромное (вся "ёмкость" знаний), но активны на каждый токен — немного (дешевле compute на инференсе при том же качестве). Используют: DeepSeek, Mixtral, предположительно GPT и Gemini (официально не всегда подтверждено), Grok. Claude — архитектура не раскрывается публично.
  - Trade-off: сложнее тренировать (load balancing между экспертами), больше VRAM для хранения всех экспертов даже при частичной активации.
- **Constitutional AI (Anthropic)**: альтернатива чистому RLHF с массовой человеческой разметкой. Явно написанный свод принципов ("конституция") → модель сама генерирует ответ → сама же критикует его на соответствие принципам → сама переписывает → эти самосгенерированные пары данных идут в тренировку (RLAIF — AI вместо человека как "судья"). Снижает объём ручной построчной разметки, масштабирует safety-тюнинг. Уязвимость: качество зависит от того, насколько полно/хорошо написана сама конституция — люди всё ещё пишут и валидируют её, просто не размечают построчно каждый ответ. Это проприетарная методология, не покупается на рынке.
