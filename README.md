# 120 Days of Backend Engineering

Это репозиторий челленджа: за 120 дней перейти из frontend-heavy разработки в backend (Java, Spring Boot, PostgreSQL, Redis, Kafka, Docker).

**Этот README для проверяющего.** Разбираться в коде не нужно. Здесь написано, что считается артефактом, где его искать и как считать неделю.

---

## Условия спора

- Старт: **Day 1 = 2026-09-14** (понедельник).
- Каждую неделю нужно **минимум 5 артефактов**.
- За каждый недостающий артефакт штраф **300 000 сум**.
  Пример: за неделю 3 артефакта, значит не хватает 2, штраф 600 000 сум.
- Время не критично: не нужно успеть ровно до 00:00. Важно, чтобы по итогу недели артефакты реально существовали и были опубликованы в репозитории.

### Недели

| Неделя | Дни        | Даты                      |
|--------|------------|---------------------------|
| 1      | Day 1–7    | 2026-09-14 — 2026-09-20   |
| 2      | Day 8–14   | 2026-09-21 — 2026-09-27   |
| 3      | Day 15–21  | 2026-09-28 — 2026-10-04   |
| …      | …          | каждая следующая +7 дней  |

Неделя N = дни с `7·(N−1)+1` по `7·N`.

## Что считается артефактом

Артефакт — это **конкретный результат, который можно открыть и посмотреть**. Не «я занимался», а файл, код или запись с выводами.

Засчитывается:

- рабочий код (новая фича или исправление в MiniBank);
- тест, особенно тест, который воспроизводит баг;
- воспроизведённая поломка («сломал систему и показал, как именно»);
- benchmark или нагрузочный эксперимент;
- эксперимент с базой данных;
- ADR (записанное архитектурное решение с вариантами и trade-offs);
- схема system design;
- разбор инцидента;
- документация;
- письменный ответ на вопрос с собеседования;
- маленький прототип;
- конспект урока **из одного выбранного курса или книги**, но только с собственными выводами;
- backend-задача с работы (без конфиденциального кода, коротко: проблема → решение → trade-offs).

**Не** засчитывается:

- «посмотрел видео» или «почитал» без письменных выводов;
- случайная статья или видео вне основного курса/книги, даже с заметками;
- один и тот же результат, записанный дважды разными словами.

## Где искать артефакты

```
.
├── README.md                  ← этот файл
├── MISSION.md                 ← зачем всё это и полные правила челленджа
├── days-progress/             ← дневник: ГЛАВНОЕ МЕСТО ДЛЯ ПРОВЕРКИ
│   └── day-0001-140926.md
├── minibank/                  ← основной проект: банковское приложение на Spring Boot
├── system-design/             ← схемы и заметки по system design
├── LEARN-LATER.md             ← список тем, отложенных на потом (это не артефакт)
└── first-bunch-of-questions.md← вопросы для baseline по знаниям
```

### Дневник `days-progress/`

Файлы называются `day-NNNN-DDMMYY.md`:

- `NNNN` — номер дня челленджа (`0001`, `0002`, …);
- `DDMMYY` — дата (`140926` = 14 сентября 2026).

В каждом файле есть разделы:

- **Сделано** — здесь артефакты. Каждый пункт ссылается на конкретный код, тест, файл или эксперимент;
- **Разобрался** — выводы и понимание (подтверждает, что урок или эксперимент был осмысленным);
- **Открытые вопросы / TODO** — что осталось. Это **не** артефакты, это план.

## Как проверять (5–10 минут в неделю)

1. Откройте файлы из `days-progress/` с датами нужной недели (см. таблицу выше).
2. Пройдите по разделам **Сделано** и выпишите артефакты.
3. Выборочно проверьте, что они реально есть:
   - код и тесты лежат в `minibank/`;
   - история коммитов (`git log` или вкладка Commits на GitHub) показывает изменения в эти даты;
   - заметки, ADR и схемы лежат в соответствующих папках.
4. Посчитайте: `штраф = max(0, 5 − количество артефактов) × 300 000 сум`.

### Как считать спорные случаи

- **Один артефакт = один законченный результат.** Пять мелких правок одной строчки не превращаются в 5 артефактов. Тест, который воспроизвёл баг, и отдельный фикс этого бага с зелёным тестом — это 2 артефакта.
- Если пункт в «Сделано» не подтверждается файлом или коммитом, он не считается.
- Задачи с работы подтверждаются короткой заметкой в дневнике (код не публикуется, потому что он конфиденциальный).
- Если сомневаетесь, спросите «что конкретно здесь можно открыть и посмотреть?». Если ответа нет, это не артефакт.

## Пример: Day 1

Из [day-0001-140926.md](days-progress/day-0001-140926.md):

1. Инициализирован проект MiniBank (Spring Boot, PostgreSQL, миграции, Docker Compose).
2. Написана логика перевода денег между счетами (`TransferService`).
3. **Воспроизведён баг тестом:** при сбое в середине перевода деньги списываются, но не зачисляются, и 200 000 UZS пропадают (`TransferServiceTest`).
4. Письменный разбор: как работают транзакции, Hibernate/JPA и почему без транзакции теряются деньги (раздел «Разобрался»).

«Прочитал MISSION.md» и настройка `CLAUDE.md` артефактами не считаются.
